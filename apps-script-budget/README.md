# Общая свадебная смета — Игнат и Лера

**Статус:** серверный и клиентский код подготовлены, начальная смета в Google Sheets. **Синхронизация заработает только после выполнения инструкции ниже и развёртывания Google Apps Script**. Сейчас GitHub Pages /budget/ — отдельная локальная версия.

## Что уже готово

- 29 статей расходов, 18 проверок, варианты подрядчиков, 4 сценария бюджета
- Закрытое хранение в исходном Google Sheets — лист `Смета_синхронизация` (скрыт)
- Персональные длинные ключи для Игната и Леры
- Автосохранение и автоматическая проверка новых изменений каждые 30 секунд
- Защита от потери чужих правок: версия + LockService + предупреждение при конфликте
- Резервная копия JSON перед заменой конфликтующей версии

## Запуск (однократно под владельцем Google-таблицы)

1. Откройте **https://script.google.com/home**, нажмите **Новый проект**. Создайте **отдельный проект**, чтобы не испортить RSVP.
2. В `Code.gs` вставьте **целиком** содержимое [Code.gs](./Code.gs).
3. Нажмите `+` → **HTML** → имя файла **Index**. Вставьте содержимое [Index.html](./Index.html). Это полный интерфейс; отдельные CSS/JS-файлы не нужны.
4. Нажмите **Сохранить**, выберите функцию `setupBudgetStorage` и нажмите **Выполнить**. Разрешите доступ к Google Sheets. В **Журнале выполнения** появятся два ключа: `IGNAT` и `LERA`. Скопируйте **каждый отдельно и храните приватно**. Эти значения также находятся в **Настройках проекта → Свойства скрипта** под именами `BUDGET_KEY_IGNAT`, `BUDGET_KEY_LERA`.
5. Нажмите **Развернуть → Новое развертывание → Веб-приложение**. **Выполнять от моего имени**, **Кому доступно: Все** (для входа без Google-авторизации Леры), затем **Развернуть**. Это даёт публичный доступ только к форме входа; чтение и запись сметы требуют длинного персонального ключа.
6. Скопируйте ссылку `https://script.google.com/macros/s/.../exec`. Откройте её в Safari на двух телефонах. Один вводит ключ Игната, второй ключ Леры. На iPhone: Поделиться → **На экран Домой**.
7. Проверка: измените одну цену на первом телефоне, дождитесь «Сохранено». На втором нажмите **Обновить** или подождите до 30 секунд. Проверьте также редактирование второго участника и кнопку резервного копирования.

## Как устроена синхронизация

Apps Script отдаёт мобильный интерфейс через собственный веб-адрес. `google.script.run` работает только внутри страницы Google Apps Script, поэтому **не надо** запускать этот `Index.html` напрямую на GitHub Pages. Сайт на GitHub Pages остаётся резервным офлайновым инструментом. В новой версии источником правды считается Google Sheets. Сохранённая на телефоне копия используется только для восстановления при ошибке, но не подменяет общий документ.

Внутри таблицы лист скрыт ради удобства, **не ради безопасности**. Любой редактор самой таблицы при желании сможет увидеть лист. Не публикуйте таблицу или ключи доступа. У сервера два отдельных ключа с высокой энтропией; имена участников нужны только для истории последнего изменения.

При одновременных правках приложение **не объединяет отдельные поля автоматически**. Вместо перезаписи показывает предупреждение: скачайте JSON-копию своих правок, затем обновите общую версию и примените изменения заново.

## Изменение кода

При последующих правках Apps Script: **Развернуть → Управление развертываниями → Изменить → Новая версия**. URL останется прежним.

**База данных:** исходная таблица «Наша свадьба · 17 и 24 июля 2027» — лист `Смета_синхронизация`. Не удаляйте его и не давайте всем пользователям таблицы права редактора без необходимости.

## Длина личных ключей

Веб-форма и сервер принимают ключи от **4 до 128 символов**, включая уже изменённые вручную в Apps Script > Свойства скрипта. Короткие ключи защищают слабо: для публичного URL настоятельно рекомендуются уникальные случайные ключи как минимум 12–16 символов. Не публикуйте ключи в GitHub.
