# Наша свадьба · RSVP v0.1.0

Приглашения для регистрации 17.07.2027 в Москве и праздника 24.07.2027 в Переславле-Залесском.

## Архитектура

GitHub Pages (`docs/`) — публичное приглашение. При ответе открывается Apps Script Web App с индивидуальной анкетой. Это позволяет использовать штатный `google.script.run` с подтверждением записи, без ненадёжного `fetch(..., mode: 'no-cors')`. Таблица остаётся закрытой; гости не видят чужих ответов. Админка находится в том же Web App, `?admin=1`.

В `docs/demo.html` можно попробовать гостевой и административный интерфейсы. Демо явно обозначено, работает только с localStorage и не пишет в Google.

## Установка серверной части

1. Создать проект на https://script.google.com/home. Добавить `Code.gs`, `App.html` из `apps-script/`. Включить отображение manifest в настройках и заменить `appsscript.json`.
2. В **Настройки проекта → Свойства скрипта** добавить:
   - `SPREADSHEET_ID`: `1qfZuxRy4TiRFFEBr8w6lipKFdZ8D1HkVE2d8vlKiF_g` — существующий свадебный планировщик.
   - `ADMIN_KEY`: случайный ключ длиной не меньше 24 символов. Не публиковать его в репозитории и не пересылать гостям.
   - `PUBLIC_URL`: URL GitHub Pages этой страницы.
3. Выполнить `install` от владельца проекта и разрешить запись в таблицы. Будет создан только лист `RSVP_Гости`; существующие листы планировщика не изменяются. Ответы пока не синхронизируются с прежним листом `Гости`.
4. **Развернуть → Новое развертывание → Веб-приложение**. Выполнять от вашего имени. Доступ: **Все**, включая гостей без Google-аккаунта. Разрешение относится к приложению, не к публичному чтению таблицы.
5. В `docs/config.js` вставить выданный URL `https://script.google.com/macros/s/.../exec` в `backendUrl` и отправить коммит.
6. Открыть `admin.html` на GitHub Pages, затем админку; ввести `ADMIN_KEY`. Создать приглашение, скопировать индивидуальную ссылку и отправить самостоятельно.
7. Проверить со второго устройства: «Иду» → запись в RSVP_Гости → изменение на «Не иду» → та же строка обновляется. Проверить, что неверный ключ не открывает админку, а другая ссылка не раскрывает список гостей.

После изменения Apps Script выпускать новую версию существующего развертывания, чтобы URL сохранился.

## Публикация GitHub

В Settings → Pages выбрать Deploy from branch, ветка `main`, каталог `/docs`. На странице не должно быть ключей, персональных ответов или файла с таблицей гостей. Публичны только исходники приложения.

## Проверка

`node prepare.mjs` — собрать автономный App.html. `node --test tests/backend.test.mjs` — проверки прав доступа, обновления существующего ответа и защиты от формул в ячейках. `node --check docs/demo-client.js` и `node --check docs/landing.js` — проверка синтаксиса.

## Ограничения прототипа

Один человек на приглашение; почта и сообщения автоматически не отправляются. Нет массового импорта гостей, удаления и автоматического пересчёта исходного листа «Гости». Ссылка-приглашение позволяет прочитать и изменить ответ именно этого человека, поэтому не размещайте её публично. Администратор входит длинным случайным ключом; для расширения проекта можно перейти на полноценную авторизацию. Квоты Apps Script ограничивают нагрузку. Обновление и исправление ручного ответа доступны в админке.
